# MultyAgent 飞书协作 · 项目总览

更新日期：2026-09-15
详细设计见 [Pi 多智能体架构设计](superpowers/specs/2026-09-14-pi-multiagent-feishu-architecture.md)

## 一、这个项目要做什么

在飞书项目群里，为六个职责角色各配一个独立机器人。成员 `@` 某个机器人提出任务，任务由该角色的 Agent 执行，结果由**同一个机器人**回到群里。复杂需求由多个角色分工协作完成。

一句话：**用飞书当前台，用 Pi Agent 当工人，用编排层当调度，让六个角色像团队一样干活。**

## 二、系统分层

```text
飞书项目群（六个机器人，各自独立应用）
        ↓
飞书接入层   长连接 · 去重 · App ID → 角色映射      ← 已完成
        ↓
任务编排层   任务表 · 依赖图 · 上下文构造 · 审批      ← 设计中
        ↓
Pi 运行时    六个独立进程，各一根 stdin/stdout      ← 设计中
        ↓
策略层       工具白名单 · 路径范围 · 风险拦截        ← 设计中
        ↓
工作区       主仓库 · 前后端 worktree · 产物仓库     ← 设计中
        ↓
观测层       任务日志 · 审计日志 · 多维表格看板       ← 设计中
```

## 三、一次任务的流转

### 简单任务（单角色，日常大多数）

```text
用户 @前端开发 修改登录页样式
  ① 接入层识别角色、去重、登记任务、回执“已接收”
  ② 编排层构造上下文（角色提示 + 任务 + 相关产物引用）
  ③ 派发给前端 Agent 的 Pi 会话
  ④ 执行：读代码、改文件、跑测试
  ⑤ 交付：交接包（结论 + 产物 + 证据 + 假设）
  ⑥ 前端机器人回帖结果
```

### 完整任务（多角色，跨模块或契约变更）

```text
用户 @项目经理 做一个手机号登录

项目经理    → 需求与验收标准（requirements.md / plan.md）
架构设计师  → 架构方案 + 接口契约（契约经人审确认后冻结）
前端开发 ┐
后端开发 ┴ → 基于同一契约并行实现，各用独立 worktree
测试       → 独立验证，产出测试报告，缺陷回派修复
审计       → 只读检查，高危发现阻断流程
集成       → 合并前跑完整测试与构建
项目经理   → 汇总交付，回帖飞书群
```

### 中途缺信息时怎么走

前端发现契约缺字段 → 不直接问后端，而是 `request_input` → 编排层先查产物仓库 → 没有就派子任务给后端 → 前端置为 `blocked` 等待 → 后端产出后编排层唤醒前端继续。

**Agent 之间不说话，但消息在流动，每一跳都经过编排层。**

## 四、六个角色

| 机器人 | 职责 | 权限边界 |
| --- | --- | --- |
| 项目经理 | 拆解需求、编排、汇总 | 不写业务代码 |
| 架构设计师 | 架构方案、接口契约、技术风险 | 代码只读，只写架构文档与契约 |
| 前端开发 | 页面、组件、交互 | 只能改前端目录 |
| 后端开发 | 接口、业务逻辑、数据模型 | 只能改后端目录 |
| 测试 | 测试设计与执行、缺陷反馈 | 默认只读，不改业务代码 |
| 审计 | 代码质量、安全、依赖、权限 | 全程只读，不修代码 |

## 五、支撑这套流程的关键机制

任务状态只有一个事实来源：`src/domain/task-store.js` 的 `TaskStore`。网关旧接口
`src/tasks.js` 仅负责把 `task_id`/`source_chat_id` 等领域字段转换为历史调用方使用的
`taskId`/`chatId` 字段；别名、最近任务、暂停和终止标志也由同一个 store 持久化，避免
看板、Trace 与运行时各自维护互相矛盾的任务状态。

| 机制 | 作用 |
| --- | --- |
| 星型协作 | 所有跨 Agent 通信经编排层，不点对点直连 |
| 产物仓库 | Agent 交换的是产物文件，不是对话 |
| 先查产物再派任务 | 防止协作退化成互相提问 |
| 交接契约 | 每次交付必带结论、产物、证据、假设 |
| 派发契约 | 下游必知：现状、任务、权限、边界 |
| 三层边界 | 系统提示告知 + 任务信封声明 + 策略层强制拦截 |
| git 隔离 | worktree 分工作区，契约用 commit 锚定版本 |
| 独立验证 | 测试不复用开发者结论，审计只读 |
| 任务分级 | L0 问答到 L3 完整链路，按影响面决定投入 |
| 单一事实来源 | 看板只是编排层状态的投影，由程序写入 |
